# 0015. Agent memory: index schema, topic extraction, and `memory` CLI

- **Status:** accepted
- **Date:** 2026-07-16
- **Deciders:** maintainer
- **Related:** ADR-0014 (knowledge/memory two-plane model — this ADR fills the deferred memory engineering); ADR-0010 (agentmesh CLI — `memory` joins its command surface, modeled on `directory`); ADR-0011 (KB branch-merge — the rebuild trigger + `.memory` race interact with it); `agent_knowledge_memory_high_level_design.md` §7–9, §11
- **Update (2026-07-24):** the recall **backend** is extended by **ADR-0033** — `memory recall` keeps its contract but reads **live** (keyword/BM25 over KB + session-records + git time-spine), so the persisted `index.json` and its rebuild/staleness path (and the `doctor` staleness warning) are **retired for routing**; embeddings/RAG remain the gated further stage, now homed in ADR-0033. The schema/extraction design below is the historical keyword-index form.

## Context

ADR-0014 adopted the two-plane model and approved the **principle** of an agent
memory layer — a computed, disposable, `.gitignore`d index rebuilt from the KB
alone, advisory to an authoritative KB — but deliberately deferred the engineering,
because the load-bearing part was hand-waved in the first draft and the review
flagged it:

- **Topic extraction** — the signal that actually drives `recall` routing was
  unspecified (headings? filenames? front-matter? full-text?). Everything else
  hinges on this.
- **"Familiarity strength"** — implied a scalar, but a static file scan yields no
  learned signal to compute one from.
- **Rebuild trigger + `.memory` race** — the index lives outside ADR-0011's
  branch-merge protection; concurrent `kb finish` rebuilds race on the shared file
  (ADR-0014 risk (e)).

This ADR resolves those. Design constraints carried from ADR-0014 and the brief:
memory must be **rebuildable from the KB alone** (§11 recovery), must **not** become
a second source of truth (§8, §13), and must let an agent recognize prior knowledge
**without loading the whole KB** (§9 success-criterion #1). No DB, no vector store,
no embeddings — that path stays gated behind a *further* ADR (ADR-0014 follow-ups).

## Options considered

**Topic extraction method**
1. **Full-text / NLP keyword extraction** — best recall, but non-deterministic,
   heavy, and pulls in a dependency the mesh's zero-infra stance rejects. A rebuild
   must be cheap and reproducible. Rejected.
2. **Embeddings** — explicitly gated behind a future ADR; reintroduces a hidden
   store. Out of scope here.
3. **Structural extraction (chosen)** — deterministic scan of each KB markdown
   file: front-matter `tags`, H1/H2 headings, and the filename stem, normalized
   (lowercase, kebab-case, de-duplicated). Zero deps, reproducible, cheap
   (~milliseconds), and good enough to *route* (its job is "which files, roughly",
   not "answer the question"). Coarseness is acceptable because memory only points;
   the KB read that follows is authoritative.

**Familiarity signal**
1. **Learned/scored strength** — no signal exists in a static scan; would require
   usage telemetry the mesh doesn't keep. Rejected as unbacked.
2. **Explicit proxy (chosen)** — `familiarity = presence + freshness + refs`, each
   a computed fact: presence (topic exists in ≥1 KB file), freshness (newest source
   mtime), refs (count of intra-KB links/mentions pointing at the source). Reported
   as those three fields, not collapsed into a fake scalar. The word "strength" is
   dropped.

**Rebuild concurrency**
1. **Lock the index** — heavier than warranted for a regenerable file. Rejected.
2. **Atomic write-and-rename (chosen)** — rebuild writes a temp file and renames
   over `index.json` (atomic on POSIX). A lost race self-heals on the next rebuild
   because the index is a pure function of the KB. No lock needed.

## Decision

Add a `memory` command group to `agentmesh` that maintains a per-agent, generated,
disposable index and answers recall queries from it.

### Index location + form
- `<agent>/.memory/index.json`, `.gitignore`d, first line/`_generated` field marks
  it "generated by `agentmesh memory rebuild` — do not edit".
- Pure function of the agent's `knowledge/` tree + its `agent.yaml` — no state that
  isn't reconstructable from those.

### Schema (`index.json`)
```json
{
  "_generated": "agentmesh memory rebuild; do not edit",
  "agent": "architect",
  "built_from_mtime": "<newest KB file mtime at build>",
  "manifest_tags": ["architecture", "adrs", "kb", "frontend", "data-pipelines"],
  "topics": [
    {
      "topic": "batch-data-pipeline",
      "sources": ["knowledge/decisions/0007-batch-data-pipeline.md"],
      "tags": ["data-pipelines", "data-architecture"],
      "freshness": "<newest source mtime>",
      "refs": 3
    }
  ]
}
```
- `topic` — normalized from front-matter `tags` ∪ H1/H2 headings ∪ filename stem.
- `sources` — KB paths the topic was extracted from (the routing target).
- `tags` — relationship tags, intersected/derived from manifest `owns`/`domains`
  (ADR-0014 cross-agent-refs rule: resolve via manifest, never hardcoded paths).
- `freshness` — newest `sources` mtime.
- `refs` — count of intra-KB links/mentions pointing at `sources` (the reference-
  count proxy).

### CLI surface (adds to ADR-0010)
| Command | Purpose |
|---|---|
| `agentmesh memory rebuild` | Scan `knowledge/` + `agent.yaml`; write `index.json` via temp+atomic-rename. Idempotent; a pure rebuild. |
| `agentmesh memory recall "<query>"` | Match query against `topics` (topic + tags), return matching `{sources, freshness, refs}` ranked by refs then freshness — **without reading source bodies**. This is retrieval stages 2–3. `--json` for machine use. |

- `recall` returns *locations + familiarity facts*, never file bodies — the caller
  then reads the KB (authoritative). Enforces §9 success-criterion #1.
- Optional `--json` on both, mirroring `directory`.

### Rebuild trigger + freshness
- `kb finish` (ADR-0011) triggers `memory rebuild` after a successful merge, so a KB
  write never leaves memory stale.
- `agentmesh doctor` warns when `index.json` is missing or `built_from_mtime` is
  older than the newest KB file (staleness), never errors (ADR-0014 tiered rule).
- Concurrent rebuilds: temp-write + atomic rename; lost race self-heals next
  rebuild (ADR-0014 risk (e)). No lock.

### Recovery (§11)
`rm -rf <agent>/.memory && agentmesh memory rebuild` fully reconstructs the index.
This is an acceptance test — no durable state may live only in memory.

## Consequences

- **Positive:** the deferred, load-bearing memory design is now concrete and
  deterministic; recall routes without loading the KB; zero new infra/deps; memory
  stays provably disposable (pure function of KB + manifest); the `.memory` race is
  closed without a lock.
- **Negative / limits:**
  - Structural extraction is coarse — a topic phrased only in body prose (no
    heading, tag, or filename) won't index. Accepted: memory routes, KB answers; if
    recall misses become common, that is the trigger to open the embeddings ADR, not
    to bolt NLP on here.
  - `refs` counts only intra-KB links/mentions; cross-agent references show up as
    manifest `tags`, not `refs`. Adequate for routing.
  - `kb finish`-triggered rebuild adds a small step to the (infrequent) KB write
    path; negligible.
- **Migration / implementation sequence:**
  1. Implement `memory rebuild` (extractor + schema + atomic write).
  2. Implement `memory recall` (query match + ranking, `--json`).
  3. Wire the post-`kb finish` rebuild hook and the `doctor` staleness warning.
  4. Add the recovery acceptance test (delete + rebuild == prior index).
  5. `.gitignore` `.memory/` in each agent during `onboard`.
- **Follow-ups:** if structural recall proves too coarse in practice, a further ADR
  gates any move to embeddings/vector search (carried from ADR-0014) — that
  reintroduces the rejected hidden-store risk and needs its own decision. Track
  recall-miss reports as the signal.
